Prefab Variant 사용으로 메인씬에 사운드설정 바 추가
메인씬에 사운드 조절 기능 추가

- Prefab Variant이란?: 일반 프리팹이 '설계도'라면, Prefab Variant는 그 설계도를 바탕으로 '살짝 수정한 파생 모델'이라고 생각하면 돼.
   1. 일반 프리팹 (부모): OptionsPanel (게임 씬에서 쓰는 원본)
   2. Prefab Variant (자식): OptionsPanel_MainMenu (메인 씬용)

- 뭐가 다른데?:
   1. 연결된 점: 만약 내가 원본 프리팹에서 사운드 조절 스크립트를 수정하거나 배경 이미지를 바꾸면, Variant에도 자동으로 적용돼. (두 번 일할 필요가 없지)
   2. 차이점(Override): 하지만 내가 Variant에서 크기를 줄이거나 특정 버튼을 비활성화하면, 그 수정 사항은 Variant에만 저장돼. 원본(게임 씬)은 절대로 변하지 않아

- 안전장치?: 걱정했던 "여기서 UI를 수정해서 게임 씬 망칠까 봐" 하는 문제! Variant를 쓰면 메인 씬에서 어떤 짓을 해도 원본 프리팹에는 아무런 영향이 없어. 오직 Variant 안에서만 노는 거니까.

- 이것만 조심해! (주의사항) Variant 인스펙터 상단에 **[Overrides]**라는 버튼이 보일 거야. 거기서 **'Apply All'**을 실수로 누르지만 마.
   1. Apply All: "자식(Variant)인 내가 수정한 이 값을 부모(원본)에게도 강제로 적용하겠다!"는 명령이야, 이것만 안 누르면 메인 씬에서 무슨 짓을 해도 게임 씬은 100% 안전해


- 메인화면 씬에서도 사운드(BGM,SFX)를 조절 할 수 있게 게임씬의 옵션창을 Prefab Variant으로 만들어서 메인화면씬에 적용했어.
- 오늘 해결한 핵심 과제: 
   1. 씬 전환 시 UI 싱글톤 유지 및 자동 연결: DontDestroyOnLoad를 사용해 메인 씬과 게임 씬에서 사운드 설정이 끊기지 않게 구현(기존 OptionManager 스크립트의 기능)
   2. 게임 씬에서만 작동하던 OptionsManager를 메인 화면(MainMenuScene)에서도 공통으로 사용할 수 있도록 구조 개선
   3. 메인 씬 전용 UI 로직 분기: 게임 씬용 버튼(Restart 등) 없이 사운드 설정창만 단독으로 뜨도록 예외 처리

- UI 이름 불일치 해결:
   1. 문제: 메인씬에 쓸 옵션 UI를 프리팹 배리언트(Variant)로 사용하면서 이름이 OptionsPanel_MainMenu로 바뀌어 코드가 오브젝트를 찾지 못했어
   2. 해결: 하이어라키의 오브젝트 이름을 코드 규칙에 맞춰 통일하거나, 코드에서 Contains 로직을 활용해 유연하게 찾도록 수정 (이름을 통일 시키는걸로 해결)

- 씬별 분기 처리:
   1. 문제: 메인 화면에서는 '게임 재시작', '나가기' 버튼이 포함된 Options 그룹이 필요 없어
   2. 해결: SceneManager.GetActiveScene().name을 이용해 현재 씬이 메인 씬일 경우 사운드 조절창(SoundControlPanel)만 바로 뜨고, 닫을 때도 패널 전체가 꺼지도록 예외 처리

- 주요 코드 로직: (핵심 요약)
   1. InitializeReferences(): 씬이 로드될 때마다 Resources.FindObjectsOfTypeAll을 통해 비활성화된 UI 요소들을 자동으로 재연결
   2. OpenSoundControls() / CloseSoundControls(): 씬에 따라 Options 그룹 활성화 여부를 결정하는 if 조건문 안전장치 추가 (코드를 수정해도 게임씬에선 문제없이 작동)

- if 조건문 안전장치 추가 이유:
   1. 씬별 분기 처리를 통해 하나의 스크립트로 여러 상황(메인/게임)을 대응하는 **재사용성(Reusability)**을 높였고, null 체크를 통해 런타임 에러(NullReferenceException)를 방지

   1. 비활성화된(SetOff) 오브젝트는 일반적인 **Find로 찾을 수 없기 때문에**, 메모리에 로드된 모든 객체를 검사하는 방식을 채택함

UI 참조 소실: DontDestroyOnLoad로 OptionsManager는 유지되지만, 씬이 바뀌면 새로운 씬에 있는 UI(버튼, 슬라이더)를 찾지 못해 기능이 먹통이 되던 문제와,
탐색 범위 오류: FindChildEx 함수가 특정 패널 내부만 뒤지느라 패널 밖에 배치된 버튼을 찾지 못했어
데이터의 영속성 vs UI의 일회성: AudioMixer와 PlayerPrefs에 저장된 소리 값은 씬이 바뀌어도 유지되지만, 새로운 씬이 로드될 때 생성된 슬라이더(Slider) 오브젝트는 항상 기본값(예: 1.0)으로 초기화됨,
시각적 불일치: 소리는 내가 설정한 대로 들리는데, 슬라이더 바는 혼자 '최대'를 가리키고 있는 상태가 발생

- 해결 과정1.: 씬 로드 대응 및 탐색 범위 확장.
- 배경: 씬이 전환되면 기존 UI 객체들은 파괴되고 새로운 객체들이 생성되므로, 싱글톤(OptionsManager)이 새 UI를 다시 찾아야 하는 문제 발생.
- SceneManager.sceneLoaded 활용:
   1. 새로운 씬이 로드될 때마다 InitializeReferences()를 자동으로 실행하도록 등록
   2. 이를 통해 드래그 앤 드롭 없이도 새 씬의 UI 오브젝트들을 **자동으로 수집**함

- SetupButton() 탐색 범위 확장 (transform.parent):
   1. 문제: 메인 메뉴에서는 버튼이 옵션 패널 내부가 아닌 **같은 계층(Canvas 직속 자식)**에 있어 기존 코드가 버튼을 찾지 못함
   2. 해결: 탐색 시작점을 패널 자신(transform)에서 **부모(transform.parent)**로 한 단계 높여, 캔버스 안의 모든 버튼을 찾을 수 있게 수정
- GameObject btnObj = FindChildEx(optionsPanel.transform, btnName);//기존: 패널 내부(자식들)만 탐색 (실패)

해결과정2.: 데이터와 UI의 시각적 동기화.
